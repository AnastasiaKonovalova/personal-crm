Отступления от `openspec/changes/keep-in-touch/design.md`:

Побочный эффект: обновление такой страницы в браузере без JS повторит отправку и добавит вторую заметку «Связались». С JS так не бывает. - CHECK в схеме с `coalesce(cadence = 'date', false)`: простое сравнение пропускало дату без частоты (NULL проходит CHECK); `design.md` поправлен

Технические решения (посмотреть код):

- `data-js` на `<html>`: inline-скрипт в `<head>` и `suppressHydrationWarning` в `layout.tsx`; без JS видны все строки блока и поле даты, кнопки блока скрыты (`globals.css`)

- Поле частоты пересоздаётся по `key` при смене значений по умолчанию: React читает `defaultValue` у `select` только при первом показе, и после ошибки формы выбор сбрасывался
- `addNoteAction` обновляет и `/`: после заметки блок меняется
- `fieldClasses` вынесены из `ui/input.tsx` для общего вида поля и `select`
- Сид: сроки считаются в днях (месяц = 30) с запасом 2 дня от границ окон; `id` контактов задаются заранее; остальные ~900 контактов теперь другие

## Страховочное правило `DOCKER-USER` на сервере

Docker публикует порты контейнеров в обход ufw. Сейчас защита одна — `/etc/docker/daemon.json` с `"ip": "127.0.0.1"`: порт без явного адреса открывается только на localhost. Явный `-p 0.0.0.0:...` или `ports: "0.0.0.0:..."` в чьём-то compose всё равно откроет порт в интернет. Правило в цепочке `DOCKER-USER` закрыло бы такой порт и в этом случае. Сервер общий с VPN — делать отдельной задачей, с проверкой VPN после.

## Дополнить правила по секретам в `AGENTS.md`

Отложено при настройке repo-safety (2026-10-16). Чего нет в разделе «Секреты и данные»:

- Не читать, не печатать, не пересказывать и не копировать значения из `.env*`, `*.pem`, `*.key`, `credentials*.json`, `token.json`, `secrets*.json` без явного узкого разрешения. `.gitignore` — правило для Git, а не граница конфиденциальности
- Не запускать `env`, `printenv`, `cat .env` без явного разрешения
- Не класть реальные доступы в отслеживаемые Git-файлы
- Проверка секретов (gitleaks) — не только перед коммитом, но и перед PR, релизом, сменой видимости репо
- Токены — на один проект, с коротким сроком жизни
- Перед установкой любого пакета — скилл check-dep
- MCP: не коммитить `.mcp.json`; токены только через `${ENV_VAR}`
- Если секрет всплыл в чате, выводе или diff: остановиться, замаскировать, предложить ротацию

## Проверить скорость работы приложения

Владелец (2026-10-22): страницы грузятся очень долго для такого простого функционала.

Замеры на проде (2026-10-29, 1000 контактов): на самом сервере главная готовится за 55–85 мс; с Mac — около 1 с, из них соединение и TLS ~0.3 с, первый байт ~0.55 с (сервер в США). То есть в проде медленно в основном из-за сети, а не приложения. Локально (`docker compose` прод-образа) — 35–90 мс на страницу.

- Сначала отделить dev от прода: в `pnpm dev` страница компилируется при первом открытии (на Intel Mac заметно) — открыть одну страницу дважды; затем `pnpm build` + `pnpm start` и пощёлкать страницы
- Если медленно и в проде — замерить по частям: запрос к базе (список с поиском по е/ё, подсчёт «Всего»), рендер серверных компонентов, загрузка шрифтов; только потом чинить
- Не путать с ложной причиной: если на `:3000` висит старый `next start`, а `pnpm dev` ушёл на `:3001`, стили отдают 500 (общая папка `.next`)
