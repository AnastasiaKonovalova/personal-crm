# Personal CRM

Личная CRM для контактов людей, которых знаю лично: кто это, откуда знакомы, телефон и почта, заметки о разговорах. Идея и главный сценарий — в `specs/01-продуктовая-идея.md`.

## Стек

Next.js (App Router) + TypeScript, React, Tailwind CSS, shadcn/ui, PostgreSQL в Docker, Drizzle ORM (схема — `src/db/schema.ts`, миграции — `drizzle/`), pnpm. К базе обращается только сервер: страницы — серверные компоненты, изменения — Server Actions.

## Требования

- Docker Desktop (запущен)
- Node.js 24 (версия в `.nvmrc`)
- pnpm

## Первый запуск

1. Создай файл с настройками из шаблона:
   ```bash
   cp .env.example .env
   ```
2. Заполни в `.env` значения `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` и `DATABASE_URL`.
   Пароль можно сгенерировать командой `openssl rand -hex 24`.
3. Запусти базу:
   ```bash
   docker compose up -d
   ```
4. Установи зависимости:
   ```bash
   pnpm install
   ```
5. Создай таблицы:
   ```bash
   pnpm db:migrate
   ```
6. Заполни базу тестовыми данными — 1000 вымышленных контактов с заметками:
   ```bash
   pnpm db:seed
   ```
   Сид срабатывает только на пустой базе: если контакты уже есть, он ничего не делает.
7. Запусти приложение:
   ```bash
   pnpm dev
   ```
   и открой http://localhost:3000

## Режимы запуска

**Разработка** — изменения в коде подхватываются сразу, страницы собираются при первом открытии:
```bash
pnpm dev
```

**Продакшен** — собранная оптимизированная версия, работает быстрее. После каждого изменения кода её нужно пересобрать:
```bash
pnpm build
pnpm start
```

В обоих случаях приложение открывается на http://localhost:3000. Остановить сервер — `Ctrl+C` в терминале, где он запущен. Одновременно может работать только один из них: оба занимают порт 3000.

## Проверки

```bash
pnpm typecheck   # проверка типов
pnpm test        # тесты: валидация и главный сценарий на настоящей базе
pnpm build       # продакшен-сборка
pnpm test:e2e    # критерии успеха через HTTP — нужно запущенное приложение (pnpm start)
```

Тестам нужна запущенная база. `pnpm test` создаёт один контакт «Тестовый Контакт …», `pnpm test:e2e` — «Проверка Сквозная …»; в конце каждый удаляет только свой контакт.

## Ручная проверка критериев успеха

1. **Список всех контактов.** Открой http://localhost:3000 — вверху «Всего: 1000», ниже таблица по алфавиту, по 50 на страницу, внизу «Страница 1 из 20».
2. **Добавил → нашёл → дописал заметку.**
   - Нажми «Добавить контакт», заполни имя (например, «Проверка Ручная»), сохрани — откроется карточка нового контакта.
   - Вернись к списку («Все контакты»), введи в поиск часть имени в любом регистре («ручн») — контакт найдётся.
   - Открой карточку, напиши заметку, нажми «Добавить заметку» — она появится в ленте с датой.
   - Обнови страницу (Cmd+R) — заметка на месте.
3. **Другой браузер.** Открой тот же адрес карточки в другом браузере (например, Safari, если до этого был Chrome) — там те же контакт и заметка. Данные лежат в базе, а не в браузере.

## База данных (PostgreSQL в Docker)

Локально в Docker работает только Postgres. Порт открыт только на `127.0.0.1`, из сети база недоступна.

### Проверка

```bash
docker compose ps
```
В колонке `STATUS` должно быть `healthy`.

Подключиться к базе через консоль:
```bash
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

### Изменение схемы

Поменяй `src/db/schema.ts`, затем:
```bash
pnpm db:generate   # создаст новую миграцию в drizzle/
pnpm db:migrate    # применит её
```

### Остановка

```bash
docker compose stop      # остановить, данные сохранятся
docker compose down      # удалить контейнер, данные сохранятся в volume
docker compose down -v   # удалить контейнер И ВСЕ ДАННЫЕ базы — необратимо
```
