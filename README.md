# Personal CRM

Личная CRM для контактов людей, которых знаю лично: кто это, откуда знакомы, телефон и почта, заметки о разговорах. Идея и главный сценарий — в `specs/01-продуктовая-идея.md`.

## Стек

Next.js (App Router) + TypeScript, React, Tailwind CSS, shadcn/ui, PostgreSQL в Docker, Drizzle ORM (схема — `src/db/schema.ts`, миграции — `drizzle/`), pnpm. К базе обращается только сервер: страницы — серверные компоненты, изменения — Server Actions.

## Требования

- Docker Desktop (запущен)
- Node.js 24 (версия в `.nvmrc`)
- pnpm

## Первый запуск

1. Создай файл с настройками из шаблона:
   ```bash
   cp .env.example .env
   ```
2. Заполни в `.env` значения `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` и `DATABASE_URL`.
   Пароль можно сгенерировать командой `openssl rand -hex 24`.
3. Запусти базу:
   ```bash
   docker compose up -d
   ```
4. Установи зависимости:
   ```bash
   pnpm install
   ```
5. Создай таблицы:
   ```bash
   pnpm db:migrate
   ```
6. Заполни базу тестовыми данными — 1000 вымышленных контактов с заметками:
   ```bash
   pnpm db:seed
   ```
   Сид срабатывает только на пустой базе: если контакты уже есть, он ничего не делает.
7. Запусти приложение:
   ```bash
   pnpm dev
   ```
   и открой http://localhost:3000

## Режимы запуска

**Разработка** — изменения в коде подхватываются сразу, страницы собираются при первом открытии:
```bash
pnpm dev
```

**Продакшен** — собранная оптимизированная версия, работает быстрее. После каждого изменения кода её нужно пересобрать:
```bash
pnpm build
pnpm start
```

В обоих случаях приложение открывается на http://localhost:3000. Остановить сервер — `Ctrl+C` в терминале, где он запущен. Одновременно может работать только один из них: оба занимают порт 3000.

## Проверки

```bash
pnpm typecheck   # проверка типов
pnpm test        # тесты: валидация и главный сценарий на настоящей базе
pnpm build       # продакшен-сборка
pnpm test:e2e    # критерии успеха через HTTP — нужно запущенное приложение (pnpm start)
```

Тестам нужна запущенная база. `pnpm test` создаёт один контакт «Тестовый Контакт …», `pnpm test:e2e` — «Проверка Сквозная …» и 51 контакт «Пагинация Проверка …» (для проверки страниц); в конце каждый удаляет только свои контакты.

## Ручная проверка критериев успеха

1. **Список всех контактов.** Открой http://localhost:3000 — вверху «Всего: 1000», ниже список по алфавиту, по 50 на страницу, внизу «Страница 1 из 20» между круглыми стрелками. Левая стрелка («Назад») на первой странице бледная и не нажимается, правая («Вперёд») открывает вторую страницу. Вся строка контакта кликабельна и открывает карточку.
2. **Добавил → нашёл → дописал заметку.**
   - Нажми «Добавить контакт», заполни имя (например, «Проверка Ручная»), сохрани — откроется карточка нового контакта.
   - Вернись к списку («Все контакты»), введи в поиск часть имени в любом регистре («ручн») — контакт найдётся.
   - Открой карточку, напиши заметку, нажми «Добавить заметку» — она появится в ленте с датой.
   - Обнови страницу (Cmd+R) — заметка на месте.
3. **Другой браузер.** Открой тот же адрес карточки в другом браузере (например, Safari, если до этого был Chrome) — там те же контакт и заметка. Данные лежат в базе, а не в браузере.
4. **Поиск по «е» и «ё».** Создай контакт «Фёдоров Проверка». Поиск «федоров» и «фёдоров» находит его в обоих случаях, и наоборот: имя с «е» находится запросом с «ё».
5. **Редактирование контакта.** На карточке нажми «Редактировать» — форма заполнена текущими данными. Сотри имя и сохрани — под полем «Имя обязательно». Впиши новые данные и сохрани — откроется карточка с ними, в списке новое имя. «Отмена» возвращает на карточку без изменений.
6. **Редактирование заметки.** У заметки нажми «Изменить», поправь текст, нажми «Сохранить» — текст обновится, дата останется прежней. Пустой текст не сохраняется: «Заметка пустая». Обнови страницу — правка на месте.
7. **Удаление контакта.** На карточке нажми «Удалить» — откроется диалог «Удалить контакт?», фокус на «Отмена». «Отмена», крестик и Esc закрывают диалог, контакт остаётся. Нажми «Удалить» в диалоге — откроется список: «Всего» на 1 меньше, контакт не находится поиском, внизу сообщение «Контакт удалён». Через 3 секунды оно исчезает, крестик закрывает сразу, после обновления страницы его нет. Старый адрес карточки отвечает «не найдено».

## База данных (PostgreSQL в Docker)

Локально в Docker работает только Postgres. Порт открыт только на `127.0.0.1`, из сети база недоступна.

### Проверка

```bash
docker compose ps
```
В колонке `STATUS` должно быть `healthy`.

Подключиться к базе через консоль:
```bash
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

### Изменение схемы

Поменяй `src/db/schema.ts`, затем:
```bash
pnpm db:generate   # создаст новую миграцию в drizzle/
pnpm db:migrate    # применит её
```

### Остановка

```bash
docker compose stop      # остановить, данные сохранятся
docker compose down      # удалить контейнер, данные сохранятся в volume
docker compose down -v   # удалить контейнер И ВСЕ ДАННЫЕ базы — необратимо
```

## Выкатка на сервер

Приложение работает на https://app.mypeoplecrm.ru. Выкатка автоматическая: **push в `main` — и через несколько минут новая версия на сервере.**

Что происходит после push (`.github/workflows/deploy.yml`):

1. **test** — GitHub Actions поднимает пустую базу, применяет миграции, запускает `pnpm typecheck` и `pnpm test`. Упали — дальше не идёт.
2. **build** — собирает Docker-образ приложения (`Dockerfile`) и кладёт в GitHub Container Registry с тегом — SHA коммита.
3. **deploy** — копирует `deploy/` на сервер в `/opt/personal-crm` и запускает `deploy/deploy.sh`: скачать образ → поднять базу → применить миграции разовым контейнером (упали — новая версия не стартует) → запустить новую версию → проверить `/health` → оставить на сервере только текущий и предыдущий образы.
4. Проверка снаружи: `https://app.mypeoplecrm.ru/health` отвечает 200.

Следить за выкаткой: вкладка **Actions** репозитория на GitHub. Зелёная галочка — выкатилось, красный крестик — нет (сервер продолжает работать на прошлой версии, если упало до шага «App»).

`pnpm start` локально пишет предупреждение `"next start" does not work with "output: standalone"` — это ожидаемо: сервер работает, а `standalone` нужен для Docker-образа.

### На сервере

- Пользователь `crm-deploy`, папка `/opt/personal-crm`: `compose.yml`, скрипты, `.env` (секреты, права 600, пишет только владелец), `image.env` / `image.env.prev` (текущая и предыдущая версия)
- docker compose, проект `prod`: `postgres` (данные в томе `prod_pgdata`) и `app` на `127.0.0.1:3000`; nginx проксирует на него `app.mypeoplecrm.ru`
- Порты наружу не открыты: база доступна только с самого сервера на `127.0.0.1:5433` (или через SSH-туннель)

Посмотреть состояние и логи (папка закрыта для других пользователей, поэтому сначала переключиться на `crm-deploy`):
```bash
ssh vps_hostkey
sudo -u crm-deploy -i
cd /opt/personal-crm
docker compose -p prod -f compose.yml --env-file .env --env-file image.env ps
docker compose -p prod -f compose.yml --env-file .env --env-file image.env logs --tail 100 app
exit
```

### Откат (только вручную)

Автоотката нет. Если новая версия сломана — вернуть предыдущую:
```bash
ssh vps_hostkey
sudo -u crm-deploy /opt/personal-crm/rollback.sh
```
Скрипт меняет местами текущую и предыдущую версии и перезапускает приложение; повторный запуск возвращает обратно. Миграции базы откат не отменяет.
