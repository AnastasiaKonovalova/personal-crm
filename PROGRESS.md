# Прогресс: Personal CRM

Рабочий журнал задачи «собрать приложение по `specs/01-продуктовая-идея.md` + 1000 тестовых контактов».
Если сессия оборвалась: прочитай этот файл, сверь с реальным состоянием (файлы, число контактов в базе) и продолжай со следующего невыполненного шага.

## Критерий готовности (/goal)

- в базе 1000 тестовых контактов
- `pnpm typecheck`, `pnpm build`, `pnpm test` проходят
- три критерия успеха из спеки подтверждены проверками
- README описывает запуск и ручную проверку

## Согласованные продуктовые решения

1. Поля контакта: имя (обязательное), кто это, откуда знакомы, телефон, почта.
2. Заметки — лента записей с датой (новые сверху), а не одно поле. «Дописал заметку» = добавил запись. Договорённости — туда же.
3. Поиск — только по имени, подстрока, без учёта регистра.
4. Список — по алфавиту, 50 на страницу, счётчик «Всего: N».
5. Не делаю: удаление контактов, редактирование полей контакта, правку/удаление заметок, теги, импорт/экспорт, вход/регистрацию, уведомления, офлайн.
6. Тестовые данные: русские имена, заведомо фиктивные телефоны и почты (домены `example.*`), у части контактов 0–5 заметок. Сид не запускается, если в базе уже есть контакты.

## Технические решения

- Каркас Next.js пишется руками (не `create-next-app`), чтобы не перезаписать README, `.gitignore`, `CLAUDE.md`.
- Доступ к базе — только сервер: модуль с `server-only`, Server Components + Server Actions, валидация zod.
- Драйвер Postgres — `postgres` (postgres.js), ORM — Drizzle, миграции — drizzle-kit.
- Переменные окружения берутся из `.env` самими Next.js / скриптами; `.env` не читается и не выводится.
- Git не инициализируется, коммитов нет.

## Блокеры (сняты)

1. **pnpm 12 не может ставить пакеты в песочнице** (`ERR_PNPM_STORE_DIR_OPEN_OPERATION_LOCK`). Решение: новые зависимости ставит пользователь сам (`pnpm install` в своём терминале). `pnpm run` в песочнице работает, только пишет предупреждение.
2. **Команды в песочнице не могли читать `.env`**. Решение: пользователь добавил `sandbox.filesystem.allowRead: ["./.env"]`.

## Решения, принятые по ходу

- check-dep: не GREEN по дате релиза — `clsx` (2024-04), `class-variance-authority` (2024-11), `tw-animate-css` (2025-09), `server-only` (2022) → не ставятся; `postgres` (2026-04, YELLOW) → заменён на `pg`. Компоненты shadcn адаптированы без cva/clsx (`cn` на одном tailwind-merge), анимации не нужны.
- Остальные пакеты GREEN: релизы и коммиты за последние 1–2 мес., не архивированы, от 17 млн загрузок в неделю. CVE-проверка (`pnpm audit`) — после установки.
- TypeScript 6.0.3, а не 7.x (7 — нативная версия на Go, совместимость с Next.js не гарантирована).
- Из `package.json` убрано поле `packageManager`: pnpm 12 из-за него пытается скачать сам себя.
- После создания контакта открывается его карточка.
- `pnpm run` в песочнице работает: pnpm пытается доустановить зависимости перед скриптом, падает на том же lock и всё равно запускает скрипт.

## Открытые вопросы к пользователю

- `pnpm-workspace.yaml` (создан pnpm при установке): `allowBuilds.esbuild` стоит заглушка «set this to true or false» — разрешать ли esbuild install-скрипт. Сейчас всё работает и без него.
- `esbuild` ≤0.24.2 (moderate) приходит транзитивно через `drizzle-kit`; касается только dev-сервера esbuild, который не используется. Можно закрыть override-ом в `pnpm-workspace.yaml` — по желанию.
- Компоненты shadcn адаптированы без `clsx`/`cva`. Если одобришь эти пакеты — можно вернуться к стандартному `shadcn init`/`add`.
- Сквозная проверка автоматизирована для формы без JavaScript; путь с JavaScript в настоящем браузере — ручная проверка по README.

## Разрешённые команды

- Проверка: `node -v`, `pnpm -v`, `docker compose ps`, `test -s .env`, `lsof -i :3000 -i :5432`, `curl --noproxy '*' …` (проверка песочницы)
- Зависимости: `pnpm add …`, `pnpm add -D …`, `pnpm install`, `pnpm dlx shadcn@latest init/add …`, `pnpm view …`
- База: `docker compose up -d`, `pnpm db:generate`, `pnpm db:migrate`, `pnpm db:seed`
- Проверки: `pnpm typecheck`, `pnpm build`, `pnpm test`, `pnpm dev` (в фоне), `curl http://localhost:…`
- Остановка только того dev-сервера, который запущен в этой сессии
- Чтение файлов проекта (`ls`, `cat`, `grep` в пределах папки проекта, кроме `.env*`)

- `docker compose down` / `rm`, `docker system prune`, действия с чужими контейнерами и процессами
- `rm`, git init/commit/push, чтение `.env`
