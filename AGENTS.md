## Как вносим изменения

### Ветки и PR

- Любое изменение - в своей ветке, имя по сути, без префиксов (`keep-in-touch`); в main только через PR
- «Начинаем фичу / доработку / правку» и `/opsx:propose` - переключись на main, забери изменения, удали локальные ветки, которых уже нет на GitHub; новая ветка от свежего main
- Перед первой правкой файлов проверь ветку: на main - забери изменения и создай новую ветку от свежего main; в рабочей ветке - продолжай в ней; ветка уже влита - новая от свежего main
- «Коммить и пуш» - коммит в текущую ветку, push, PR в main; дай ссылку на PR
- После merge - переключись на main, забери изменения, удали ветку локально
- Изменения выкатки (workflows, скрипты в `deploy/`) - тем же путём, через PR

### Правка и фича

- Мелкая правка, в том числе небольшое изменение модели данных - план в режиме планирования, ветка, PR
- Фича - полный цикл: требования → план → реализация по шагам. Инструмент любой, например OpenSpec
- Фича готова, когда выполнены критерии приёмки из её спеки

### Проверки

- `pnpm typecheck`, `pnpm test` - после каждого шага
- Полный прогон (база, сборка, e2e) - `zsh scripts/checks.sh`, вывод в `tmp/checks.log`; скриншоты эскизов - `zsh scripts/mockup-shots.sh`, вывод в `tmp/shots/`. Оба скрипта только локально, не в git
- Перед сборкой остановить `pnpm dev`: сборка и dev пишут в одну `.next`. Если `pnpm dev` пишет «Port 3000 is in use» - на 3000 висит старый сервер (стили там отдают 500), остановить его

### Проверка в браузере

- Живое приложение (ховер, фокус, формы) - через Claude in Chrome на `localhost:3000`; расширение подключает владелец
- Данные в базе не создавать: ошибки проверять пустыми формами; сохранение покрывают e2e
- Команды расширению - по одной, не пачкой; открыта только своя вкладка с расширением. Иначе действия падают с «Couldn't determine which page this action targets»
- Окно не шире 937px, `resize_window` его не сужает: ширину 390 смотреть через iframe 390px, вставленный в страницу через `javascript_tool` (как в `scripts/mockup-shots.sh`)
- Фокус с клавиатуры - `el.focus({focusVisible: true})`; стиль читать через ~400ms: `transition-colors` анимирует и цвет рамки

## Выкатка

### Окружения и сервер

- На сервере docker compose, проект `prod` (`-p prod`)
- Сервер общий для приложения и лендинга: чужие ключи, папки и настройки nginx на нём не удаляй и не меняй - только добавляй своё; удалить - только с согласия владельца
- Диск сервера не забивается: после удачной выкатки оставляй только текущий и предыдущий образы, логи контейнеров ограничь по размеру

### Как выкатываем

- Скрипты выкатки - в `deploy/` в репо, выкатка копирует их на сервер; в workflow только их вызов
- Merge в main → образ с тегом SHA коммита → GHCR → на сервере: миграции → новый образ → smoke `/health`
- Миграции - отдельный шаг до старта нового образа: разовый контейнер из того же образа применяет миграции и завершается; упали миграции - новый образ не стартует
- После выкатки скажи, как проверить

### Сбой и откат

- Красный smoke - выкатка упала, сообщи владельцу. Сам ничего не откатывай, автооткат в скрипты не ставь: откат только вручную, запускает владелец
