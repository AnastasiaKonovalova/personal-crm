# Proposal

## Why

Поздравить человека с днём рождения - простой повод напомнить о себе, ради которого и ведётся личная CRM. Сейчас дату рождения негде записать, и приложение не подсказывает, кого скоро поздравлять: владелец узнаёт об этом из других приложений или пропускает.

## What Changes

- У контакта новое необязательное поле «День рождения»: день и месяц, год - по желанию. Задаётся в формах создания и редактирования, без JavaScript тоже работает
- Для 29 февраля владелец выбирает, когда отмечать в невисокосный год: 28 февраля (по умолчанию) или 1 марта
- Дата проверяется на сервере: несуществующий день («31 апреля», «29 февраля» в невисокосный год), день без месяца, будущая дата или год раньше 1900 не сохраняются
- В карточке контакта среди данных - строка «День рождения» («25 ноября 1990», «25 ноября» без года; у 29 февраля - и выбор для невисокосного года)
- На главной над блоком «Пора связаться» - блок «Скоро день рождения»: контакты, у которых день рождения был вчера, сегодня или в ближайшие 7 дней. Сверху - опоздавшие (вчера), дальше - ближайшие; при равенстве - по имени. В строке - имя, когда («Вчера», «Сегодня», «Завтра», «Послезавтра», «Через 3 дня»), дата и, если год известен, возраст. Строка открывает карточку
- Блок показывается по тем же правилам, что «Пора связаться»: первая страница списка без поиска, с фильтром по группе и на странице группы - только контакты группы. Нет дней рождения в окне - блока нет
- Как у «Пора связаться»: число контактов у заголовка, первые 5 строк и «Показать все (N)», раскрытый блок по 10 на страницу с пагинацией и «Свернуть» - на месте, без перезагрузки; без JavaScript - все строки сразу
- В строке блока - кнопка «Поздравил(а)» с иконкой торта: добавляет в карточку заметку «Поздравил(а)» так же, как «Связались» (срок в «Пора связаться» пересчитывается), и убирает строку из блока до следующего дня рождения; без JavaScript работает обычной формой. Подтверждения пока нет - отдельная доработка после выкатки
- Модель данных: пять новых необязательных столбцов у `contacts` (день, месяц, год, выбор для 29 февраля, день последнего поздравления). Миграция только добавляет столбцы, существующие контакты остаются без даты рождения

## Capabilities

### New Capabilities

- `contact-birthdays`: дата рождения контакта - ввод и проверка, показ в карточке, блок «Скоро день рождения» на главной и на странице группы

### Modified Capabilities

- `data-ownership`: блок «Скоро день рождения» показывает только контакты текущего пользователя (требования «Только свои данные на экранах» и «Новый пользователь»)

## Impact

- База: `src/db/schema.ts` - столбцы `birth_day`, `birth_month`, `birth_year`, `birth_leap_day`, `birth_congratulated_on` и CHECK, миграция Drizzle `0004`; тест миграции в `tests/migration-on-data.test.ts`
- Расчёты: новый `src/lib/birthdays.ts` - ближайший день рождения, дни до него, возраст, тексты строки; поверх общих функций дат из `src/lib/keep-in-touch.ts`, окно в 7 дней - общее с «Пора связаться»
- Валидация: `src/lib/validation.ts` - поля даты рождения в схеме контакта
- Сервер: `src/server/contacts.ts` - сохранение даты, `listBirthdays` для блока (с фильтром по группе), `congratulate` (заметка - общей с `addNote` функцией)
- Действия: `src/app/contacts/actions.ts` - новые поля формы, `congratulateAction`
- Экраны: форма контакта (`src/components/contact-form.tsx`), карточка (`src/app/contacts/[id]/page.tsx`), главная (`src/app/page.tsx`) и страница группы (`src/app/groups/[id]/page.tsx`) - новый блок; кнопки раскрытия и пагинация выносятся из `src/components/reminders-block.tsx` в общий компонент обоих блоков
- Дизайн: эскизы поля, строки карточки и блока в `design/`, решения - в `design/README.md`; утверждает владелец до кода экранов
- Сид: даты рождения у части демо-контактов, в окне - больше 10, включая вчера и сегодня; 29 февраля с обоими выборами; один уже поздравленный
- Тесты: юнит-тесты расчётов и валидации, интеграционные на базе, e2e по HTTP (Vitest), Playwright - раскрытие, пагинация и блок без JavaScript
- Новых зависимостей нет
