# Spec Delta

## Purpose

Делит данные между пользователями: у каждого контакта и группы есть владелец, и пользователь видит и меняет только свои записи — в интерфейсе и в любом запросе к серверу.

## ADDED Requirements

### Requirement: Владелец записи
У каждого контакта и каждой группы MUST быть владелец — пользователь, который их создал. Заметки MUST принадлежать владельцу контакта. Запись без владельца MUST NOT существовать.

#### Scenario: Новый контакт
- **WHEN** пользователь A создаёт контакт
- **THEN** владелец контакта — A, контакт есть в списке A

#### Scenario: Новая группа из формы контакта
- **WHEN** пользователь A в форме контакта создаёт новую группу
- **THEN** владелец группы — A

### Requirement: Только свои данные на экранах
Пользователь MUST видеть только свои записи: в списке контактов и его числе «Всего», в поиске, в карточке, в заметках, на странице «Группы» и в числе контактов группы, на странице группы, в фильтре по группе, в блоке «Пора связаться», в выборе групп в форме контакта.

#### Scenario: Список и поиск
- **WHEN** у A есть контакт «Илья Морозов», а B ищет «Морозов»
- **THEN** у B контакта нет ни в списке, ни в результатах поиска, и «Всего» у B его не считает

#### Scenario: Пора связаться
- **WHEN** у контакта A просрочен срок связи
- **THEN** в блоке «Пора связаться» у B этого контакта нет

#### Scenario: Группы и фильтр
- **WHEN** у A есть группа «Соседи»
- **THEN** у B её нет на странице «Группы», в фильтре на главной и в выборе групп в форме контакта

### Requirement: Чужая запись как несуществующая
Чужой контакт или чужая группа по прямой ссылке MUST показывать тот же экран, что и несуществующие. Запрос к серверу с номером чужой записи — чтение, правка, удаление, заметка, «Связались», частота, добавление в группу и удаление из неё — MUST NOT читать или менять запись и MUST отвечать так же, как для несуществующей.

#### Scenario: Чужой контакт по ссылке
- **WHEN** B открывает адрес карточки контакта A
- **THEN** B видит тот же экран, что и для несуществующего контакта

#### Scenario: Чужая группа по ссылке
- **WHEN** B открывает адрес страницы группы A
- **THEN** B видит тот же экран, что и для несуществующей группы

#### Scenario: Правка чужого контакта запросом
- **WHEN** B отправляет на сервер правку, удаление, заметку или «Связались» с номером контакта A
- **THEN** контакт A и его заметки не меняются, B получает ответ как для несуществующего контакта

#### Scenario: Чужая группа в запросе
- **WHEN** B отправляет переименование или удаление с номером группы A, или сохраняет свой контакт с отметкой группы A
- **THEN** группа A не меняется, контакт B в группу A не попадает

#### Scenario: Свой контакт в чужую группу
- **WHEN** B добавляет свой контакт в группу, указав номер группы A
- **THEN** членства не появляется, группа A не меняется

### Requirement: У каждого свои группы
Пользователи MUST иметь возможность создавать группы с одинаковыми именами независимо друг от друга.

#### Scenario: Две группы «Друзья»
- **WHEN** у A есть группа «Друзья», и B создаёт группу «Друзья»
- **THEN** группа создаётся у B; у каждого по одной группе «Друзья» со своими контактами

### Requirement: Новый пользователь
Новый пользователь MUST видеть пустой список контактов с подсказкой «Добавь первый контакт», без групп и без блока «Пора связаться».

#### Scenario: Первый вход
- **WHEN** человек впервые вошёл
- **THEN** список контактов пуст, видна подсказка «Добавь первый контакт», на странице «Группы» групп нет

### Requirement: Существующие данные достаются владельцу
Все контакты, заметки и группы, которые есть в базе до выкатки входа, MUST после выкатки принадлежать пользователю с почтой владельца приложения. Число контактов, заметок, групп и членств в группах MUST после выкатки совпадать с числом до неё; содержимое записей MUST NOT меняться.

#### Scenario: Выкатка на базе с данными
- **WHEN** выкатывается вход на базу с контактами, заметками и группами
- **THEN** владелец входит под своей почтой и видит все прежние контакты с их заметками, частотой и группами; число записей в каждой таблице то же

#### Scenario: Другой пользователь после выкатки
- **WHEN** после выкатки входит человек с другой почтой
- **THEN** он не видит ни одной прежней записи

### Requirement: Демо-данные у владельца
Демо-данные для проверки MUST создаваться у пользователя с почтой владельца.

#### Scenario: Сид
- **WHEN** на локальной базе заполняются демо-данные, и владелец входит под своей почтой
- **THEN** демо-контакты и группы видны ему и не видны пользователю с другой почтой
