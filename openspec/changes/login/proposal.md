# Proposal

## Why

Приложением хотят пользоваться друзья владельца, но сейчас все видят одни и те же контакты: пользователей в приложении нет. Нужно, чтобы каждый входил под своей почтой и видел и менял только свои контакты, заметки и группы. Исходные требования — `specs/02-пользователи-вход.md`.

## What Changes

- Вход только по ссылке из письма (Better Auth, плагин MagicLink). Паролей нет; первый вход и есть регистрация, имя не спрашиваем
- Новые экраны: страница входа (почта + «Получить ссылку»), «Ссылка для входа отправлена на <почта>», «Ссылка устарела, запроси новую». В шапке появляются почта пользователя и «Выйти»
- Правила ссылки: одноразовая, живёт 15 минут, новая ссылка гасит старые. Лимит — 3 письма на одну почту за 10 минут. Почта нормализуется (обрезка пробелов, регистр не важен) и проверяется на сервере
- Сессия держится 30 дней с последнего захода на устройстве. Можно войти с нескольких устройств, выход действует только на текущем
- Письма уходят через Nodemailer. Куда — решают настройки: локально и в CI в почтовую заглушку Mailpit (Docker), на сервере в Resend. Сборка для всех окружений одна
- **BREAKING**: без входа приложение не открывается. Каждый запрос к серверу отдаёт и меняет только данные текущего пользователя: у контактов и групп появляется владелец. Чужая запись выглядит как несуществующая: тот же общий экран «Не нашлось»
- **BREAKING**: имя группы теперь уникально только среди групп одного пользователя. У A и B может быть по группе «Друзья»
- Миграция на данных: все существующие контакты, заметки и группы, а также демо-данные сида, передаются пользователю с почтой владельца. Ни одна запись не теряется. Откат только вместе: база из бэкапа перед выкаткой и прошлая версия приложения
- Новый пользователь видит пустой список и подсказку «Добавь первый контакт»
- e2e на вход двух пользователей A и B через Mailpit. Существующие e2e (главный сценарий и остальные) перед началом входят под своим пользователем

## Capabilities

### New Capabilities

- `user-auth`: вход по ссылке из письма, письмо и куда оно уходит, правила ссылки и лимит писем, сессия и выход, почта в шапке
- `data-ownership`: у каждой записи есть владелец; пользователь видит и меняет только своё во всех экранах и запросах к серверу; новый пользователь начинает с пустого списка; существующие данные передаются владельцу приложения

### Modified Capabilities

- `contact-groups`: требование «Имя группы» — уникальность имени действует в пределах групп одного пользователя, а не всей базы

## Impact

- **Зависимости (новые)**: `better-auth`, `nodemailer`, `@types/nodemailer`. Перед установкой — проверка через check-dep и согласование с владельцем
- **База**: таблицы Better Auth (`user`, `session`, `verification`, `account`); `user_id` в `contacts` и `groups`; уникальный индекс групп становится `(user_id, normalized name)`. Миграция меняет существующие данные, поэтому до merge её нужно показать владельцу
- **Код**: все функции `src/server/contacts.ts` и `src/server/groups.ts` получают `userId`; страницы и server actions сначала берут сессию; новые маршруты `/login`, `/api/auth/[...all]`; шапка в `src/app/layout.tsx`; `EmptyList`; сид
- **Тесты**: интеграционные тесты и e2e создают своих пользователей; новый e2e входа A/B; помощник входа через Mailpit API
- **Docker и CI**: сервис Mailpit в `docker-compose.yml` и в CI (`ci.yml`); новые переменные в `.env.example` (секрет Better Auth, URL приложения, SMTP, отправитель, почта владельца `OWNER_EMAIL`)
- **Сервер**: новые переменные в `.env` на сервере и в `deploy/compose.yml`; ключ Resend; домен `mail.crm.<домен>` подтверждается в Resend записями DNS — это делает владелец. В README — заметка про откат с бэкапом
- **Документация**: `AGENTS.md` — снять пометки «запланировано» у Better Auth и Mailpit; убрать пункт «Вход по MagicLink» из `specs/backlog.md`
