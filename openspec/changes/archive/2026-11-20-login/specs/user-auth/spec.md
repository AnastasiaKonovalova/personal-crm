# Spec Delta

## Purpose

Даёт каждому человеку войти в приложение под своей почтой по ссылке из письма, без паролей, и выйти на текущем устройстве.

## ADDED Requirements

### Requirement: Без входа приложение закрыто
Любая страница приложения без входа MUST вести на страницу входа: поле почты и кнопка «Получить ссылку». Запрос к серверу на чтение или изменение данных без входа MUST отклоняться. Проверка `/health` MUST работать без входа.

#### Scenario: Открыл приложение без входа
- **WHEN** человек без входа открывает главную страницу
- **THEN** он видит страницу входа с полем почты и кнопкой «Получить ссылку»

#### Scenario: Прямая ссылка без входа
- **WHEN** человек без входа открывает адрес карточки контакта или страницы «Группы»
- **THEN** он видит страницу входа, данные не показываются

#### Scenario: Отправка формы без входа
- **WHEN** запрос на создание контакта приходит без входа
- **THEN** контакт не создаётся

#### Scenario: Проверка здоровья без входа
- **WHEN** без входа запрашивают `/health`
- **THEN** ответ 200, как и раньше

### Requirement: Запрос ссылки
Человек MUST получать ссылку для входа, вводя почту. Паролей MUST NOT быть. Первый вход по ссылке MUST создавать пользователя: отдельной регистрации нет, имя не спрашивается. После отправки MUST показываться «Ссылка для входа отправлена на <почта>», одинаково для новой и для известной почты.

#### Scenario: Ссылка для новой почты
- **WHEN** человек вводит почту, под которой ещё никто не входил, и нажимает «Получить ссылку»
- **THEN** он видит «Ссылка для входа отправлена на <почта>», письмо со ссылкой приходит на эту почту

#### Scenario: Ссылка для известной почты
- **WHEN** человек вводит почту уже существующего пользователя
- **THEN** он видит тот же текст «Ссылка для входа отправлена на <почта>», письмо приходит

#### Scenario: Первый вход создаёт пользователя
- **WHEN** человек впервые открывает ссылку из письма
- **THEN** он внутри приложения, в шапке его почта; формы регистрации и вопроса об имени не было

### Requirement: Нормализация почты
Пробелы по краям почты MUST обрезаться, регистр букв MUST NOT различаться. Почты, которые отличаются только этим, MUST вести к одному пользователю.

#### Scenario: Почта с пробелами и большими буквами
- **WHEN** пользователь с почтой `anna@example.com` есть, и человек запрашивает ссылку для ` Anna@Example.COM `
- **THEN** письмо уходит на `anna@example.com`, после входа по ссылке он внутри под тем же пользователем и видит его контакты

### Requirement: Проверка почты
Неверный адрес почты MUST давать ошибку под полем «Проверь адрес почты», письмо MUST NOT уходить. Сервер MUST проверять почту по тем же правилам, даже если запрос пришёл не из формы.

#### Scenario: Неверный адрес в форме
- **WHEN** человек вводит `anna@` и нажимает «Получить ссылку»
- **THEN** под полем ошибка «Проверь адрес почты», введённый текст остаётся в поле, письмо не уходит

#### Scenario: Пустая почта
- **WHEN** человек нажимает «Получить ссылку» с пустым полем
- **THEN** под полем ошибка «Проверь адрес почты», письмо не уходит

#### Scenario: Неверный адрес в запросе мимо формы
- **WHEN** запрос ссылки приходит на сервер напрямую с почтой `not-an-email`
- **THEN** запрос отклоняется, письмо не уходит

### Requirement: Срок и одноразовость ссылки
Ссылка MUST работать один раз и не дольше 15 минут. Запрос новой ссылки MUST гасить все прежние ссылки этой почты. Старая или уже использованная ссылка MUST вести на экран «Ссылка устарела, запроси новую» с кнопкой на страницу входа и MUST NOT впускать.

#### Scenario: Ссылка открыта второй раз
- **WHEN** человек вошёл по ссылке, вышел и открывает ту же ссылку снова
- **THEN** он видит «Ссылка устарела, запроси новую» и кнопку на страницу входа, вход не происходит

#### Scenario: Ссылке больше 15 минут
- **WHEN** человек открывает ссылку через 15 минут после её отправки
- **THEN** он видит «Ссылка устарела, запроси новую», вход не происходит

#### Scenario: Запросил новую ссылку
- **WHEN** человек запросил ссылку, потом запросил ещё одну и открывает первую
- **THEN** он видит «Ссылка устарела, запроси новую»; вторая ссылка впускает

#### Scenario: Кнопка на экране устаревшей ссылки
- **WHEN** на экране «Ссылка устарела, запроси новую» человек нажимает кнопку
- **THEN** открывается страница входа

### Requirement: Лимит писем
На одну почту MUST уходить не больше 3 писем за 10 минут. Сверх лимита письмо MUST NOT уходить, человек MUST видеть «Слишком часто, попробуй через несколько минут» вместо текста об отправке.

#### Scenario: Четвёртый запрос за 10 минут
- **WHEN** человек запросил ссылку для одной почты три раза и в те же 10 минут запрашивает в четвёртый
- **THEN** он видит «Слишком часто, попробуй через несколько минут», четвёртое письмо не уходит

#### Scenario: Лимит после пробелов и регистра
- **WHEN** три запроса были для `anna@example.com`, а четвёртый за те же 10 минут — для `ANNA@example.com `
- **THEN** он видит «Слишком часто, попробуй через несколько минут», письмо не уходит

#### Scenario: Лимит одной почты не мешает другой
- **WHEN** лимит для `anna@example.com` исчерпан, и человек запрашивает ссылку для `boris@example.com`
- **THEN** он видит «Ссылка для входа отправлена на boris@example.com», письмо приходит

#### Scenario: После 10 минут снова можно
- **WHEN** с первого из трёх запросов для почты прошло больше 10 минут
- **THEN** новый запрос даёт «Ссылка для входа отправлена на <почта>», письмо приходит

### Requirement: Письмо для входа
Письмо MUST приходить от «Свои люди - Личная CRM» с адреса `noreply@mail.crm.<домен>` с темой «Ссылка для входа в «Свои люди»». Письмо обращается на «ты». В тексте MUST быть кнопка «Войти», указание, что ссылка работает 15 минут, и фраза «Если вход запрашивал(а) не ты - просто проигнорируй письмо».

#### Scenario: Содержимое письма
- **WHEN** человек запросил ссылку
- **THEN** в заглушке Mailpit письмо от «Свои люди - Личная CRM» с темой «Ссылка для входа в «Свои люди»», в нём кнопка «Войти» со ссылкой входа, срок 15 минут и фраза про игнорирование

### Requirement: Куда уходят письма
Куда уходят письма, MUST решаться настройками окружения, а не кодом: одна и та же сборка MUST отправлять письма в заглушку Mailpit на компьютере владельца и в автотестах и через Resend на сервере. Автотесты MUST NOT отправлять настоящие письма. Локально MUST получаться войти под любым адресом через заглушку.

#### Scenario: Письмо локально
- **WHEN** на компьютере владельца человек запрашивает ссылку для выдуманной почты
- **THEN** письмо появляется в Mailpit, вход по ссылке оттуда проходит

#### Scenario: Письмо в автотесте
- **WHEN** автотест в CI запрашивает ссылку
- **THEN** письмо появляется в Mailpit этого прогона, наружу не уходит

#### Scenario: Письмо на сервере
- **WHEN** на сервере человек запрашивает ссылку для своей настоящей почты
- **THEN** письмо приходит в его настоящий ящик

### Requirement: Сессия
Вход MUST держаться 30 дней с последнего захода на этом устройстве. Пользователь MUST иметь возможность быть в приложении с нескольких устройств одновременно.

#### Scenario: Заход продлевает вход
- **WHEN** пользователь вошёл, заходил на 20-й день и открывает приложение на 40-й день
- **THEN** он внутри без нового входа

#### Scenario: 30 дней без захода
- **WHEN** пользователь не открывал приложение на этом устройстве больше 30 дней
- **THEN** он видит страницу входа

#### Scenario: Два устройства
- **WHEN** пользователь вошёл на телефоне и на компьютере
- **THEN** на обоих он внутри одновременно

### Requirement: Шапка и выход
В шапке MUST быть почта пользователя и кнопка «Выйти». «Выйти» MUST завершать вход только на текущем устройстве и вести на страницу входа.

#### Scenario: Почта в шапке
- **WHEN** пользователь внутри приложения
- **THEN** в шапке его почта и кнопка «Выйти»

#### Scenario: Выход
- **WHEN** пользователь нажимает «Выйти»
- **THEN** открывается страница входа; главная без нового входа больше не открывается

#### Scenario: Выход на одном устройстве
- **WHEN** пользователь вошёл на двух устройствах и нажал «Выйти» на одном
- **THEN** на втором он по-прежнему внутри

### Requirement: Главный сценарий входа для двух пользователей
Вход и разделение данных MUST проверяться автотестом в браузере на двух пользователях A и B, со ссылками входа из заглушки Mailpit. Этот автотест MUST быть отдельным от автотеста главного сценария из `specs/01-продуктовая-идея.md`.

#### Scenario: A и B
- **WHEN** A вошёл по ссылке и добавил контакт, затем B вошёл по своей ссылке
- **THEN** у B контакта A нет ни в списке, ни в поиске, а прямая ссылка на контакт A показывает тот же экран, что и несуществующий контакт
