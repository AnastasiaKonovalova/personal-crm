# Proposal

## Why

Форма «Получить ссылку» вызывает Better Auth напрямую из server action, мимо его HTTP-входа `/api/auth/*`, поэтому его лимит по IP (5 запросов в минуту) на форму не действует. Владелец проверила на проде (2026-11-25): 12 запросов подряд прошли все. С одного IP можно запросить письма входа на сколько угодно разных адресов, по 3 на каждый: это нагрузка на почтовый ключ и спам чужим ящикам с нашего домена.

## What Changes

- Свой лимит по IP: с одного IP уходит не больше 10 писем входа за час, на любые адреса. Сверх лимита письмо не уходит, человек видит то же «Слишком часто, попробуй через несколько минут» (решение владельца 2026-11-25)
- Лимит работает и для формы, и для прямого запроса на `/api/auth/sign-in/magic-link`: проверка в том же хуке, что и лимит на адрес
- IP берётся только из `X-Real-IP`: его ставит nginx (`$remote_addr`), клиент его не подделает. `X-Forwarded-For` не читаем: первое значение в нём присылает клиент
- Без `X-Real-IP` (локально, e2e без заголовка) лимит по IP не действует; лимит на адрес работает как раньше
- Лимит по IP и лимит на адрес проверяются в одной транзакции: одновременные запросы не обходят ни один из них
- В `login_emails` - колонка `ip` (может быть пустой) и индекс по IP и времени; миграция только добавляет, существующие строки не меняет
- Лимит Better Auth по IP на HTTP-входе остаётся как есть

## Impact

- `src/db/schema.ts`, новая миграция `drizzle/0005_*.sql`, `tests/migration-on-data.test.ts`
- `tests/e2e/login.e2e.ts`, `tests/e2e/auth.ts` (заголовок `X-Real-IP` в запросе ссылки)
- Сервер: nginx уже передаёт `X-Real-IP` на проде и тест-стенде, менять не нужно
- Откат на прошлую версию безопасен: старый код колонку `ip` не читает, она может быть пустой
