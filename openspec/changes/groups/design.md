# Design

## Context

Мотивация - `proposal.md`, требования - `specs/contact-groups/spec.md` и дельта `specs/keep-in-touch/spec.md`.

Сейчас в базе две таблицы: `contacts` и `notes` (`notes.contact_id` с `ON DELETE CASCADE`). Весь доступ к данным идёт через `src/server/contacts.ts`, формы - через server actions в `src/app/contacts/actions.ts`, валидация на zod в `src/lib/validation.ts`. Формы и кнопки работают без JavaScript: id идут скрытыми полями, а не через `.bind()` (Next.js 16.4). Поиск по имени уже сравнивает «е» и «ё» как одну букву (`translate(name, 'Ёё', 'Ее')`). Главная хранит состояние в адресе: `?q=` и `?page=`. Строка общего списка - целиком ссылка `<a>` на карточку (`src/app/page.tsx`), колонки сетки `1.1fr 1.4fr 1.4fr 20px`, на ≤680px - только имя, «Кто это» и шеврон.

## Goals / Non-Goals

**Goals:**
- Связь «многие ко многим» между контактами и группами, без потери данных при удалении любой стороны
- Уникальность имени группы гарантирует база, а не только форма
- Всё работает без JavaScript, как остальные формы; всплывашка «+N» - тоже

**Non-Goals:**
- Фильтр по нескольким группам сразу, вложенные группы, цвета и иконки групп
- Массовое добавление контактов в группу из списка
- e2e и CI - позже (`specs/backlog.md`)

## Decisions

### 1. Две таблицы: `groups` и `contact_groups`

- `groups`: `id uuid`, `name text not null`, `created_at timestamptz`
- `contact_groups`: `contact_id` → `contacts.id` и `group_id` → `groups.id`, обе ссылки `ON DELETE CASCADE`, первичный ключ `(contact_id, group_id)`, индекс по `group_id` для фильтра
- Удаление контакта убирает его членства; удаление группы убирает её членства, контакты не трогает

Альтернатива - массив `group_ids uuid[]` в `contacts`: нет внешних ключей, удаление группы пришлось бы чистить руками. Отклонено.

### 2. Уникальность имени - индекс в базе

Уникальный индекс по выражению `lower(translate(name, 'Ёё', 'Ее'))`. Нормализация в коде - та же (`foldYo` + `lower`), чтобы форма и база считали одинаково. Нарушение индекса (Postgres `23505`) превращается в ошибку поля «Такая группа уже есть» - ловится и гонка двух вкладок. Длина - zod (≤ 50) и `CHECK (char_length(name) <= 50)`.

Альтернатива - только проверка в коде перед вставкой: пропускает дубль при двух одновременных запросах. Отклонено.

### 3. «Новая группа» в контакте - найти или создать

Одна операция `findOrCreateGroup(name)` для форм и карточки: `insert ... on conflict do nothing`, затем выбор по нормализованному имени. Имя существующей группы - не ошибка, контакт просто попадает в неё (спека «В „Новая группа“ имя существующей»). На странице «Группы» то же имя - ошибка «Такая группа уже есть»: там цель - именно новая группа.

Поле «Новая группа» в форме - одно имя за сохранение. Несколько новых групп - сохранить ещё раз или добавить из карточки.

### 4. Сохранение групп контакта - в одной транзакции с контактом

Форма шлёт `groupIds` несколькими значениями одного поля (чекбоксы) и `newGroup`. Сначала валидируется всё (контакт и имя новой группы), затем одна транзакция: сохранить контакт → найти или создать новую группу → удалить строки контакта в `contact_groups` → вставить отмеченные и новую. Ошибка в любом поле - ничего не пишется, отметки и текст возвращаются в форму. Несуществующие id отбрасываются.

### 5. Группы в карточке - плашки с крестиком и одно поле (эскиз `design/contact-groups-a.html`)

- Плашки групп контакта по алфавиту; название - ссылка на страницу группы `/groups/<id>` (п.12), крестик - убрать из группы
- Одно поле «Группа: выбрать или новая» с `<datalist>` всех групп, где контакта ещё нет, и кнопка «Добавить». Сервер делает `findOrCreateGroup` (п.3) и добавляет контакт: имя существующей группы - добавление, новое имя - создание
- Крестик - ссылка `?removeGroup=<groupId>`: сервер рисует карточку с открытым диалогом «Убрать из группы «…»?» (`design/contact-groups-remove.html`), «Убрать» - POST-форма, «Отмена» и крестик диалога - ссылка на карточку без параметра. Так подтверждение работает и без JavaScript. С JavaScript ссылку перехватывает тот же `AlertDialog`, что у удаления контакта, без перехода; фокус на «Отмена»
- Действия `addContactToGroupAction` и `removeContactFromGroupAction` меняют только членство, остальные поля контакта не трогают; без JS - redirect в карточку, как «Связались»

Альтернатива - галочки всех групп + «Сохранить»: владелец выбрала плашки.

### 6. Группы в строке списка

Сервер отдаёт для каждой строки все группы контакта по алфавиту (одним запросом `array_agg` по `contact_groups` для контактов страницы). Сколько показать, решает CSS, а не JS:

- Три ширины (решение 22 в `design/README.md`): шире 1100px видно до 3 групп, 681–1100px - до 2, до 680px - 1. В разметке выводятся первые 3 группы и до трёх значков «+N» - по одному на ширину (всего − 3, всего − 2, всего − 1), у каждого своя всплывашка; CSS по ширине экрана скрывает лишние группы и значки. Расчёт видимых групп и N для каждой ширины - чистая функция с юнит-тестом. Образец - `design/contacts-groups.html` и `design/app.css`
- Группы получают свою колонку сетки на широком экране и свою строку под «Кто это» на узком; колонка фиксированной доли, чипсы с `max-width` и многоточием - не сжимают другие колонки (спека «Длинное имя группы»)
- Границы - 680px (уже есть в списке) и 1100px (добавлена: на 900 три группы не помещались). На средней ширине колонки строки - `1fr 1.2fr 1fr 1.3fr`, на широкой - `1fr 1.2fr 1fr 1.6fr`, плашка не шире 9em

Альтернатива - мерить ширину строки в JS (`ResizeObserver`) и показывать столько, сколько влезет: точнее, но мигает при загрузке и не работает без JS. Отклонено.

### 7. Всплывашка «+N» - встроенный `popover`

Значок «+N» - `<button popovertarget>`, всплывашка - элемент с атрибутом `popover`: открытие по клику и тапу, закрытие по Escape и вне её дают браузер и без JavaScript, фокус и доступность - тоже. Наведение мышью - маленький клиентский скрипт (`showPopover()` по `pointerenter` для `pointerType === "mouse"`, закрытие с задержкой по `pointerleave`). Кнопка с `popovertargetaction="show"`: после открытия наведением клик её не закрывает. Место - под «+N», правые края совпадают; ставит тот же скрипт по `getBoundingClientRect` (CSS anchor positioning есть не во всех браузерах), при прокрутке всплывашка закрывается. Рабочий образец - в `design/contacts-groups.html`.

Строка сейчас целиком `<a>`, а кнопка внутри ссылки - недопустимая разметка. Строка перестраивается: ссылка на карточку растягивается на всю строку через псевдоэлемент (`after:absolute after:inset-0`), «+N» лежит поверх (`relative z-10`) - тот же приём, что у «Связались» в строке блока. Клик по «+N» не открывает карточку.

Альтернатива - Radix `Popover` из уже установленного `radix-ui`: требует JS для открытия. Встроенный `popover` есть во всех текущих браузерах; новой зависимости нет в обоих случаях.

### 8. Фильтр - параметр `?group=<id>` на главной

`listContacts({ query, page, groupId })` и `listReminders({ groupId })` добавляют условие `exists (select 1 from contact_groups ...)`. Счётчик и ссылки страниц несут `group`; форма поиска несёт его своим списком групп. Несуществующий или битый id - фильтр игнорируется. Блок «Пора связаться» показывается с фильтром, если в группе есть контакты; считает пустые состояния по группе.

Вид (эскиз `design/contacts-filter.html`): нативный `select` отдельной строкой под строкой поиска, подпись «Фильтр по группам» - внутри того же поля над значением (одна рамка на подпись и значение, `select` занимает всё поле), первый вариант - «Все группы». Поиск и фильтр - одна форма: без JS оба применяются кнопкой «Найти», с JS группа - сразу при выборе. Сброс группы - вариант «Все группы» (`?q=` остаётся), отдельной кнопки нет. «Сбросить» после «Найти» - только поиск (`?group=` остаётся), появляется, когда поиск задан; для скринридера - «Сбросить поиск». «Найти» и «Сбросить» - одна группа без переноса внутри: если не помещаются рядом с полем поиска, обе уходят на следующую строку (так и в поиске без фильтра). Отклонены: пилюли всех групп над блоком (A) и прокручиваемая строка (C).

### 9. Переключатель «Контакты» / «Группы»

Две ссылки в виде сегментов над блоком «Пора связаться» на главной и в том же месте на `/groups`; текущая - `aria-current="page"`. «Контакты» ведут на `/` без параметров. Вид - решение 21 в `design/README.md`: паттерн `LangSwitch`, текущий раздел - `accent` с `ink`.

### 10. Страница `/groups`

Серверная страница: список групп с числом контактов одним запросом (`left join` + `count`), название группы - ссылка на страницу группы `/groups/<id>` (п.12), форма «Новая группа», у каждой - переименование на месте (по ссылке `?edit=<id>`, без JS) и удаление с подтверждением тем же приёмом, что «Убрать из группы» (п.5): «Удалить» - ссылка `?delete=<id>`, сервер рисует страницу с открытым диалогом «Удалить группу «…»?» (эскиз `design/groups-delete.html`, вид - решение 12), «Удалить» в диалоге - POST-форма, «Отмена» - ссылка без параметра; с JavaScript ссылку перехватывает `AlertDialog` без перехода, фокус на «Отмена». Действия - в `src/app/groups/actions.ts`, доступ к данным - в `src/server/groups.ts` с тем же `safeWrite` (в логах только код ошибки, без имён групп).

### 11. Сид

`src/db/seed.ts` создаёт 6-8 выдуманных групп, одна - с именем на 50 символов; часть контактов в одной группе, часть в 2-5 группах, часть без групп.

### 12. Страница группы `/groups/[id]`

Два входа к контактам группы - разные сценарии (решение 30 в `design/README.md`): фильтр на главной (п.8) сужает общий список и остаётся на главной; страница группы - работа только с одной группой. На страницу группы ведут название группы на `/groups` (п.10) и плашка в карточке (п.5); плашки в строке общего списка - не ссылки.

- Серверная страница `src/app/groups/[id]/page.tsx`. Название - `findGroup(id)`; группы нет (удалена или битый id) - `notFound()`, как у карточки удалённого контакта
- Данные - те же `listContacts({ query, page, groupId })` и `listReminders({ groupId })`, что у главной с фильтром; блок «Пора связаться» - по тем же правилам: первая страница, без поиска, в группе есть контакты
- Шапка (эскиз `design/group.html`): ссылки «Все группы» (`/groups`) и «Все контакты» (`/` без параметров) в столбик над заголовком; заголовок «Контакты» с подзаголовком «в группе <название>» внутри `h1`; «Всего: N» без поиска, «Найдено: N» с поиском. Переключателя и фильтра нет
- Поиск - форма с `action="/groups/<id>"` и только `q`; «Сбросить» - ссылка на `/groups/<id>`; ссылки страниц - `/groups/<id>?q=&page=`. Пустая группа - «В группе пока никого нет» (эскиз `design/group-empty.html`)
- «Добавить контакт» - `/contacts/new?group=<id>`: форма создания отмечает эту группу, если она существует; битый или удалённый id игнорируется, форма открывается без отметки. С существующей группой «Отмена» и «Все контакты» в форме ведут на `/groups/<id>`, иначе - на `/` (решение владельца 2026-11-13)
- Разметка списка контактов (строки, шапка списка, пустое состояние, страницы) выносится в общий компонент для главной и страницы группы, чтобы строки не расходились

Альтернатива - страница группы на главной (`/?group=` без переключателя и фильтра): тогда выбор группы в фильтре уводил бы с общего списка, и сценарий «фильтр в общем списке» пропадал. Отклонено.

## Risks / Trade-offs

- [Строка-ссылка перестраивается - может сломаться ховер, фокус и e2e общего списка] → сохранить `focus-visible` и ховер на всей строке; прогнать `zsh scripts/checks.sh`
- [CSS решает, сколько групп видно, по ширине экрана, а не по длине названий - на 681–1100px длинные названия обрезаются сильнее] → принято (решение 22): строка не «прыгает» при загрузке и работает без JS
- [Наведение мышью открывает всплывашку случайно при движении по списку] → небольшая задержка открытия (~150 мс)
- [Много групп - длинный выпадающий список] → нативный `select` прокручивается сам; группы по алфавиту
- [Удалённая группа в старой ссылке] → на главной фильтр игнорируется, а не 404; на странице группы - 404, как у удалённого контакта (спека)
- [Два входа к контактам группы - фильтр на главной и страница группы - могут разойтись в виде строк] → общий компонент списка (п.12)
- [Битые `groupIds` из формы] → отбрасываются сервером

## Migration Plan

Миграция только создаёт `groups`, `contact_groups` и индексы; существующие таблицы не меняет - риск минимальный (см. backlog «Проверка миграций на данных»). Выкатка - обычным путём: миграции → новый образ → smoke `/health`. Откат кода безопасен: старый код новые таблицы не читает.
