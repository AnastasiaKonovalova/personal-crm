# Design

## Context

Мотивация - `proposal.md`, требования - `specs/contact-groups/spec.md` и дельта `specs/keep-in-touch/spec.md`.

Сейчас в базе две таблицы: `contacts` и `notes` (`notes.contact_id` с `ON DELETE CASCADE`). Весь доступ к данным идёт через `src/server/contacts.ts`, формы - через server actions в `src/app/contacts/actions.ts`, валидация на zod в `src/lib/validation.ts`. Формы и кнопки работают без JavaScript: id идут скрытыми полями, а не через `.bind()` (Next.js 16.4). Поиск по имени уже сравнивает «е» и «ё» как одну букву (`translate(name, 'Ёё', 'Ее')`). Главная хранит состояние в адресе: `?q=` и `?page=`. Строка общего списка - целиком ссылка `<a>` на карточку (`src/app/page.tsx`), колонки сетки `1.1fr 1.4fr 1.4fr 20px`, на ≤680px - только имя, «Кто это» и шеврон.

## Goals / Non-Goals

**Goals:**
- Связь «многие ко многим» между контактами и группами, без потери данных при удалении любой стороны
- Уникальность имени группы гарантирует база, а не только форма
- Всё работает без JavaScript, как остальные формы; всплывашка «+N» - тоже

**Non-Goals:**
- Фильтр по нескольким группам сразу, вложенные группы, цвета и иконки групп
- Массовое добавление контактов в группу из списка
- e2e и CI - позже (`specs/backlog.md`)

## Decisions

### 1. Две таблицы: `groups` и `contact_groups`

- `groups`: `id uuid`, `name text not null`, `created_at timestamptz`
- `contact_groups`: `contact_id` → `contacts.id` и `group_id` → `groups.id`, обе ссылки `ON DELETE CASCADE`, первичный ключ `(contact_id, group_id)`, индекс по `group_id` для фильтра
- Удаление контакта убирает его членства; удаление группы убирает её членства, контакты не трогает

Альтернатива - массив `group_ids uuid[]` в `contacts`: нет внешних ключей, удаление группы пришлось бы чистить руками. Отклонено.

### 2. Уникальность имени - индекс в базе

Уникальный индекс по выражению `lower(translate(name, 'Ёё', 'Ее'))`. Нормализация в коде - та же (`foldYo` + `lower`), чтобы форма и база считали одинаково. Нарушение индекса (Postgres `23505`) превращается в ошибку поля «Такая группа уже есть» - ловится и гонка двух вкладок. Длина - zod (≤ 50) и `CHECK (char_length(name) <= 50)`.

Альтернатива - только проверка в коде перед вставкой: пропускает дубль при двух одновременных запросах. Отклонено.

### 3. «Новая группа» в контакте - найти или создать

Одна операция `findOrCreateGroup(name)` для форм и карточки: `insert ... on conflict do nothing`, затем выбор по нормализованному имени. Имя существующей группы - не ошибка, контакт просто попадает в неё (спека «В „Новая группа“ имя существующей»). На странице «Группы» то же имя - ошибка «Такая группа уже есть»: там цель - именно новая группа.

Поле «Новая группа» в форме - одно имя за сохранение. Несколько новых групп - сохранить ещё раз или добавить из карточки.

### 4. Сохранение групп контакта - в одной транзакции с контактом

Форма шлёт `groupIds` несколькими значениями одного поля (чекбоксы) и `newGroup`. Сначала валидируется всё (контакт и имя новой группы), затем одна транзакция: сохранить контакт → найти или создать новую группу → удалить строки контакта в `contact_groups` → вставить отмеченные и новую. Ошибка в любом поле - ничего не пишется, отметки и текст возвращаются в форму. Несуществующие id отбрасываются.

### 5. Группы в карточке - отдельная форма, как частота

Блок «Группы» в карточке со своей формой (без JS - обычный POST и redirect в карточку, как «Связались»): отметки всех групп + «Новая группа» + «Сохранить». Действие `setContactGroupsAction` меняет только членства, остальные поля контакта не трогает. Вид - чипсы с крестиком или отметки - решает эскиз; спека описывает только поведение.

### 6. Группы в строке списка

Сервер отдаёт для каждой строки все группы контакта по алфавиту (одним запросом `array_agg` по `contact_groups` для контактов страницы). Сколько показать, решает CSS, а не JS:

- В разметке выводятся первые 3 группы и два значка: «+N» для широкого экрана (N = всего − 3) и «+M» для узкого (M = всего − 1). На ≤680px 2-я и 3-я группы и широкий значок скрыты, на широком - узкий значок. Расчёт N и M - чистая функция с юнит-тестом
- Группы получают свою колонку сетки на широком экране и свою строку под «Кто это» на узком; колонка фиксированной доли, чипсы с `max-width` и многоточием - не сжимают другие колонки (спека «Длинное имя группы»)
- Граница «узкий/широкий» - существующие 680px; если в эскизе три группы не влезают на средних ширинах, добавить промежуточную точку

Альтернатива - мерить ширину строки в JS (`ResizeObserver`) и показывать столько, сколько влезет: точнее, но мигает при загрузке и не работает без JS. Отклонено.

### 7. Всплывашка «+N» - встроенный `popover`

Значок «+N» - `<button popovertarget>`, всплывашка - элемент с атрибутом `popover`: открытие по клику и тапу, закрытие по Escape и вне её дают браузер и без JavaScript, фокус и доступность - тоже. Наведение мышью - маленький клиентский скрипт (`showPopover()` по `pointerenter` для `pointerType === "mouse"`, закрытие с задержкой по `pointerleave`).

Строка сейчас целиком `<a>`, а кнопка внутри ссылки - недопустимая разметка. Строка перестраивается: ссылка на карточку растягивается на всю строку через псевдоэлемент (`after:absolute after:inset-0`), «+N» лежит поверх (`relative z-10`) - тот же приём, что у «Связались» в строке блока. Клик по «+N» не открывает карточку.

Альтернатива - Radix `Popover` из уже установленного `radix-ui`: требует JS для открытия. Встроенный `popover` есть во всех текущих браузерах; новой зависимости нет в обоих случаях.

### 8. Фильтр - параметр `?group=<id>` на главной

`listContacts({ query, page, groupId })` и `listReminders({ groupId })` добавляют условие `exists (select 1 from contact_groups ...)`. Счётчик, пагинация, поиск (скрытое поле) несут `group`. Несуществующий или битый id - фильтр игнорируется. Блок «Пора связаться» показывается с фильтром, если в группе есть контакты; считает пустые состояния по группе. Вид и место фильтра - решается в эскизе.

### 9. Переключатель «Контакты» / «Группы»

Две ссылки в виде сегментов над блоком «Пора связаться» на главной и в том же месте на `/groups`; текущая - `aria-current="page"`. «Контакты» ведут на `/` без параметров. Вид - эскиз.

### 10. Страница `/groups`

Серверная страница: список групп с числом контактов одним запросом (`left join` + `count`), форма «Новая группа», у каждой - переименование на месте (по ссылке `?edit=<id>`, без JS) и удаление через диалог, как «Удалить контакт?» (`AlertDialog`, решение 12 дизайна). Действия - в `src/app/groups/actions.ts`, доступ к данным - в `src/server/groups.ts` с тем же `safeWrite` (в логах только код ошибки, без имён групп).

### 11. Сид

`src/db/seed.ts` создаёт 6-8 выдуманных групп, одна - с именем на 50 символов; часть контактов в одной группе, часть в 2-5 группах, часть без групп.

## Risks / Trade-offs

- [Строка-ссылка перестраивается - может сломаться ховер, фокус и e2e общего списка] → сохранить `focus-visible` и ховер на всей строке; прогнать `zsh scripts/checks.sh`
- [CSS решает, сколько групп видно, по точке 680px - на промежуточных ширинах три группы могут не влезть] → проверить в эскизе на 681-1024px; при необходимости промежуточная точка или 2 группы
- [Наведение мышью открывает всплывашку случайно при движении по списку] → небольшая задержка открытия (~150 мс)
- [Много групп - фильтр занимает пол-экрана] → решить вид фильтра в эскизе на 15 группах
- [Удалённая группа в старой ссылке] → фильтр игнорируется, а не 404 (спека)
- [Битые `groupIds` из формы] → отбрасываются сервером

## Migration Plan

Миграция только создаёт `groups`, `contact_groups` и индексы; существующие таблицы не меняет - риск минимальный (см. backlog «Проверка миграций на данных»). Выкатка - обычным путём: миграции → новый образ → smoke `/health`. Откат кода безопасен: старый код новые таблицы не читает.
