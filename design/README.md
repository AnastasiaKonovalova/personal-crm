# Эскизы экранов

Эскизы — статичный HTML на токенах дизайн-системы (`ak-design-system/`, не в git). Они — эталон вида приложения: правка дизайна идёт сначала в эскизе, владелец её утверждает, потом она переносится в код. Как дизайн-система устроена в коде — `src/design-system/README.md`.

Эскизы собраны по коду приложения (2026-11-22): разметка повторяет компоненты из `src/`, их классы Tailwind переписаны обычным CSS в `app.css` на тех же токенах. Как и код, эскизы берут из дизайн-системы только токены, без её `ak-`классов.

Эскиз правится за пару строк, код приложения при этом не трогается. Отклонены: Claude Design / canvas (дорогой перенос в код — эскиз не на токенах), сразу в Next.js (правки засоряют код до утверждения), снимок HTML с работающего приложения (Tailwind собирает только классы, которые уже есть в коде; разметка Next шумная), публикация эскизов на claude.ai (владелец решил — только локально).

## Правила

- Один экран — один эскиз. Состояния экрана (ошибки, пустые, диалоги, другой статус) — внутри него, а не отдельными файлами
- Фича меняет экран — правка вносится в эскиз этого экрана и согласуется в нём; нового файла под фичу нет. Новый экран — новый файл
- Код поменял экран без эскиза — эскиз догоняет код в той же правке
- Данные в эскизах выдуманные

## Как смотреть

```bash
open design/index.html
```

`index.html` — обзор: каждое состояние каждого экрана в 1280 (уменьшено вдвое) и 390. Заголовок экрана или состояния открывает его целиком: там можно кликать, кнопки переключают состояния. Скриншоты — `zsh scripts/mockup-shots.sh` (см. `AGENTS.md`): по файлу на состояние и ширину.

## Как устроен эскиз

- Подключение: `vendor/fonts.css` → `vendor/tokens.css` → `app.css`; в конце `<body>` — `states.js`
- Состояние — в адресе: `contact.html#overdue`, без `#` — `default`. Элемент с `data-state="a b"` виден только в состояниях `a` и `b`, без атрибута — всегда. Для правок только стиля есть `html[data-state="…"]`
- Список состояний с названиями — в `<meta name="states">` файла; его читает скрипт скриншотов. В `index.html` тот же список — в массиве `SCREENS`: новое состояние добавлять в оба места
- Эскизы самодостаточны: токены и шрифты лежат копией в `vendor/`. Если дизайн-система поменяется — обновить копии. `vendor/styles.css` (компоненты дизайн-системы) нужен только архиву

| `contact.html` | карточка `/contacts/<id>`: основное, просрочено, частота не задана, конкретная дата с ошибкой, «Сохранено», без групп, «Убрать из группы?», «Удалить контакт?», правка заметки с ошибкой, заметок нет |
| `contact-form.html` | форма `/contacts/new` и `/contacts/<id>/edit`: новый контакт, со страницы группы, конкретная дата, групп ещё нет, редактирование, ошибки полей |
| `groups.html` | `/groups`: основное, ошибка создания, переименование с ошибкой, «Удалить группу?», групп нет |
| `group.html` | страница группы `/groups/<id>`: основное, поиск, пустая группа с длинным названием |

| `vendor/` | копии `fonts.css`, `tokens.css`, `styles.css` из `ak-design-system/` |
| `archive/` | эскизы до сборки по коду (по фичам, кусками); не обновляются. Номера решений ниже ссылаются на них |

Экран чужого или несуществующего контакта не рисуем: это существующий `not-found.tsx`.
