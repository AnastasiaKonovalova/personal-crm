## Зачем так

Эскизы — статичный HTML на токенах и `ak-`классах дизайн-системы. Правка стоит пару строк и обновление вкладки, код приложения не трогается. После утверждения разметка переносится на React-компоненты.

Рассмотрены и отклонены:
- Claude Design / canvas — правки удобные, но перенос в код дорогой: эскиз собран не на `ak-`классах и токенах
- сразу в Next.js (роут `/design`) — каждая правка идёт через React/Tailwind/shadcn, засоряет код до утверждения
- публикация эскизов как Artifact на claude.ai — владелец отказался, только локально

## Как смотреть

```bash
open design/index.html
```

`index.html` — обзор: каждый экран в 1280 (уменьшен вдвое) и 390. Заголовок экрана открывает его целиком.

Эскизы самодостаточны: стили дизайн-системы лежат копией в `design/vendor/` (`fonts.css`, `tokens.css`, `styles.css` из `ak-design-system/`). Если дизайн-система поменяется — обновить копии.

## Задачи на будущее (вне переноса, делать отдельно)

- **Шрифты в репо через `next/font/local`.** Сейчас `next/font/google` скачивает Space Grotesk и Manrope при каждой сборке: сборка зависит от сети (в песочнице агента `pnpm build` падает, CI зависит от доступности Google Fonts). Решение: положить `.woff2` (Space Grotesk 400–700 латиница, Manrope 400–800 латиница + кириллица, ~6 файлов, ~200–300 КБ) в репо и подключить через `next/font/local` с теми же `variable`. Проверить лицензию (обе — SIL OFL, можно класть в репо)
- **Предупреждение pnpm `ERR_PNPM_IGNORED_BUILDS`.** pnpm не запускает install-скрипты `esbuild@0.18.20`, `esbuild@0.25.12`, `esbuild@0.28.2` и просит `pnpm approve-builds`. Было до переноса, сборке и тестам не мешает. Разобраться: откуда три версии esbuild (чьи зависимости), нужен ли им install-скрипт (бинарь под платформу) и разрешить точечно через `onlyBuiltDependencies` / `pnpm approve-builds` — после проверки безопасности, как для новой зависимости
